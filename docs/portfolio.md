# CommerceLens 求职材料

## 项目简介

CommerceLens 面向电商经营与物流分析，把自然语言问题转成可追溯的 SQL 和指标调查。系统基于分层抽样的 Olist 订单，展示逾期率、商品金额和分组贡献，并输出证据与执行轨迹。通过真实模型对照实验，定位查询可执行性与答案正确性的差距。

## 简历要点

- 按月份比例分层抽样构建 15,000 笔 Olist 订单及关联表，定义支付金额、商品金额和逾期率口径，用独立计算复核 36 条业务参考 SQL。
- 用 LangGraph 编排 SQL、指标调查和 BM25 业务知识检索，结合只读 DuckDB、工具限制与结果对账，在 Streamlit 展示指标、分母分子、数据不足及可导出的证据链。
- 设计 Olist 业务回归评测和 DataBench 改编子集实验。表结构提示与定向重试在独立 48 题 Holdout 上将答对数从 3 提升到 15；额外语义提示降至 12，据此保留为可选实验。

## 面试问题与参考回答

### 如何避免把订单支付额重复记到商品类别？

一笔订单可包含多条支付和多件商品。支付先按订单汇总，再按用户州或购买月分析。商品类别用商品行的价格，排除运费。两个指标共用购买窗口，但采用不同粒度。我用源表独立 SQL 核对总额，用分组贡献加回尾部组核对总变化，避免把分类汇总误称为净营收。

### 如何保留证据，又避免把错误 SQL 当作可用结果？

LangGraph 把工具提案、执行和验证分开，模型根据模式及 BM25 找到的业务定义生成计划。SQL 经过关系和函数允许列表，然后进入只读、禁用外部访问的 DuckDB。调查工具另外核对分组贡献之和。界面保留 SQL、输入分母、检索到的口径及轨迹。库存问题返回证据不足，展示无法确认的原问题。

### 为什么测试集答对数仍然低于 SQL 执行数？

SQL 能执行只能说明它通过了语法、绑定和运行检查。历史 33 条可执行错答中，17 条把是非题变成计数或中间值，6 条附带了多余列。在已接触的 80 题上，消融显示 DDL 提示贡献大于定向重试。冻结后的独立 Holdout 上，两者组合答对 15/48，额外语义提示只答对 12/48。结果支持继续研究输出语义和列名处理，外推范围限于这些改编子集。Olist 金标准仍等候独立人工复核。
